# Pre-1929 English Bible translations with **no digital text** — PDF / scan links

_Compiled 2026-10-28 from the Internet Bible Catalog ([bibles.wikidot.com](https://bibles.wikidot.com/indexpage), all 1,030 entries on 806 pages read). Each title was searched for a born-digital, verse-segmented text in eBible.org, CrossWire/SWORD, MySword, MyBible (ph4.org), theWord-modules.com (196 module pages), gratis.bible, Zefania, Project Gutenberg (GUTINDEX.ALL, Oct 2026), bolls.life, GitHub and the commercial module sites — and, since revision 6, the studybible.info parallel-text library (162 version codes, see `STUDYBIBLE_SOURCES.md`). None was found: the only known witness is a page scan, or nothing at all._

- **97** entries with a **verified** downloadable PDF (link resolved and the response begins `%PDF-`)
- **26** entries whose only located copy is a **Google Books record** (its PDF endpoint refused this sandbox with HTTP 429 — the link is a catalogue entry, not a tested download)
- **4** entries where no digital copy of any kind was found (they are repeated in section D so that the list is complete on its own)
- **12** further titles with **no copy anywhere** (listed at the end)

> ⚠️ **Scans are page images with an OCR text layer — not clean text.** Measured on Whiston 1745, the one volume where both forms are available: the scan's text layer recovers **61.6 %** of the correct words (long-s → f, w → vv, one text object per word, running heads and catchwords mixed into verses), against **99.7 %** from a born-digital PDF. Every entry here needs OCR correction or manual transcription before it can enter the dataset. That is why they are excluded from it.

Links: **PDF** = direct download (HTTP-verified) · **Item** = Internet Archive details page (DjVu text, other formats, sometimes a better scan) · **Google** = Google Books record · **Catalog** = the wikidot entry with full bibliographic detail. Years are publication dates; where the catalogue is inconsistent the printing described in its `Date:` line is used.

## How the links were checked

Each Internet Archive item was resolved through its metadata API, the full PDF file name read from that metadata, and the file requested directly; a link is printed as a **PDF** only when the response began with `%PDF-`. Items that answered with an error are shown as **Item** links so the record is still reachable. Google Books PDF downloads could not be tested: every endpoint (`books.google.com/books/download/…`, the country mirrors, and title-based URLs) returned HTTP 429 from this sandbox, and the Books API likewise; only the `jscmd=SearchWithinVolume2` endpoint answered, which yields snippets rather than text. Titles whose catalogue page listed no scan at all were searched through the Internet Archive advanced-search API.

Machine-readable data: `pipeline/research_scan_links.json`, `pipeline/research_ia_pdf_meta.json`, `pipeline/research_ia_search_groupd.json`, `pipeline/research_no_digital_copy.json`; the builder is `pipeline/build_pdf_only_list.py`.
